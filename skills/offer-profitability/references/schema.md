# Calculator contract, version 1

Run `python3 scripts/evaluate.py INPUT.json` or `--help`. All currency amounts use the same currency and are JSON numbers, without symbols. Rates/fractions use 0 to 1. Calculations use Decimal; output numbers are rounded to six decimals. This is expected-value analysis, not a provider's per-transaction rounding engine. No dependencies, network, account writes or secrets.

Start with the [synthetic product example](../examples/discounted-product.json). For a service, inspect the [capacity example](../examples/fixed-scope-service.json). Example rates are invented inputs, not recommended fee schedules or benchmarks.

## Required inputs

| Field | Meaning |
|---|---|
| `schema_version` | Exactly `1`. |
| `offer_name`, `currency`, `period` | Nonempty context strings. State when delivery and refund outcomes mature. Currency is a label, with no conversion. |
| `price` | Actual total item/service price per placed order after discounts, excluding collected tax and shipping. A bundle is one complete basket. |
| `shipping_charged` | Shipping revenue per placed order, excluding tax. Zero for an explicitly shipping-free scope. |
| `tax_collected` | Pass-through tax per order, used only when a fee has base `charge`. Not revenue. |
| `costs_complete` | Boolean confirming all relevant variable delivery costs have been considered. False means missing data. |
| `costs` | Array of `{name, amount, kind}`. Unique names; amount per placed fulfilled order. Kind `inventory` means landed product cost; `cash` means other variable expense such as shipping or paid labor; `opportunity` means unpaid owner time or another noncash sacrifice. Include refunds' additional costs below, never here as well. Empty means explicitly no such costs. |
| `fees` | Array of `{name, rate, fixed, base}`. Original per-order fee is `rate * base + fixed`. Unique names. Base `items` = price; `revenue` = price + shipping; `charge` = price + shipping + tax. Use separate lines for different bases. Empty means explicitly no fees. |
| `refunds` | Array described below. Empty means explicitly no refund effect included in this case. |
| `cac_per_order` | Acquisition cost divided by this cohort's placed acquired orders, including later-refunded orders. Use the same scope throughout. Zero must be explicit; count variable selling costs once. |
| `orders` | Nonnegative integer placed orders over `period`. A supplied scenario, never a demand forecast generated by this script. |

Normalize known nonapplicable inputs to zero or empty arrays. A missing/null required value returns `status: missing_data` and its paths, with no economics. It is not a loss verdict. Malformed types, negative costs, impossible probabilities and unknown keys are errors. There is no automatic cost discovery: a complete but incorrect assertion remains incorrect.

## Refund outcomes

Each entry has every field below. Outcomes are mutually exclusive, with total probability <= 1. The residual is an order with no refund. A partial refund is a refund outcome, not a fully kept order.

| Field | Meaning |
|---|---|
| `name`, `probability` | Unique name and fraction of placed orders with this outcome. |
| `item_refund_fraction` | Fraction of original `price` refunded. |
| `shipping_refund_fraction` | Fraction of original `shipping_charged` refunded. |
| `fee_credit_fractions` | Object containing every fee name and fraction of that entire original fee credited for this outcome. Explicit zero for retained fees. This is independent of the revenue-refund fraction. |
| `extra_cost` | Net additional merchant return label, handling, refund fee and other expense per such outcome, excluding original costs. Nonnegative. |
| `inventory_recovery` | Recoverable original inventory cost per such outcome, between zero and original total `inventory` cost. Returned stock value is not cash or future sale revenue. Zero for a service without inventory. |

All original delivery costs are incurred. Do not use for pre-fulfillment cancellations with avoided delivery, multiple currencies, taxes borne as expenses, exchanges, chargebacks, subscriptions or indefinite support. Model these separately. Tax refunds are pass-through and only appear in a separately supplied cash schedule.

## Optional inputs

Omitted or null `fixed`, `capacity` or `cash` means **not assessed**, not zero. An incomplete supplied block returns missing data, so omit a block when only unit economics is needed.

- `list_price`: reference item subtotal before discount. Output reports the discount; never subtracts it again.
- `fixed: {period, incremental}`: existing period fixed expense and additional fixed expense caused by this offer, each nonnegative. Use explicit zeros if none. `modeled_operating_result_before_tax` subtracts both. `contribution_less_incremental_fixed_cost` leaves existing fixed expense out. Neither proves causal incremental profit. Include every expense needed for the claimed profit scope. Financing, depreciation and unpaid labor are excluded unless explicitly supplied in the appropriate cost fields.
- `capacity`: provide integer `max_orders` and/or both `available_hours` and positive `hours_per_order`. Hours include expected support/rework. The lowest limit applies. Also provide `displaced_contribution_per_order`, zero when this volume displaces no alternative work. This is economic sacrifice, additional to costs. Do not also include it in an opportunity cost line. Requested volume is flagged, never silently reduced.
- `cash: {starting_cash, complete, events}`: signed starting balance; boolean completeness assertion; events `{day, label, amount}` with nonnegative integer day and signed movement. Daily movements are netted, so this is closing-day liquidity, not intraday funding. Include all applicable tax, inventory and payout movements. `complete: false` gives a partial schedule and cannot establish adequate funding. The schedule is independently supplied, not generated or reconciled to the profit model.
- `evidence`: object keyed by JSON pointer or parent subtree, including `/` for the whole case. Entries `{status, source, as_of}` use `observed`, `quoted`, `assumed` or `derived`; source/date are nonempty strings. The closest parent applies. `derived` must identify inputs/formula in its source. Unattributed numbers remain visible. The calculator does not verify records or dates.
- `sensitivity`: array `{name, overrides: {"/numeric/path": value}}`. Targets must be existing numeric input leaves, excluding schema version, evidence, cash and sensitivity. Joint changes allowed; modified values are labeled assumed scenarios. Example: `{"name":"Higher CAC", "overrides":{"/cac_per_order":30}}`. No automatic uncertainty ranges or demand response.

## Output

Success returns `status: calculated`; exit 0. `assessment` describes the modeled constraint, never unconditional business viability. Missing economics also exits 0 with `status: missing_data`, `missing_data` and `audit.input`. Invalid data or unreadable JSON writes `error: ...` to stderr and exits 2 without JSON stdout.

| Object | Important fields |
|---|---|
| `per_placed_order` | `expected_net_revenue`, original costs/fees, expected refund effects, `expected_contribution_before_ads`, `expected_contribution_after_ads`, `opportunity_cost`, `expected_economic_contribution_after_ads`. Opportunity cost is excluded from operating contribution and deducted from economic contribution. `fee_rows` and `refund_rows` expose the bridge. |
| Kept-order fields | `kept_order_probability`; `kept_order_contribution_after_ads` is a no-refund order's own contribution. `cohort_contribution_allocated_per_kept_order` = expected cohort contribution / no-refund probability, null when zero. This allocation includes refund losses and is not a survivor's own margin. Neither includes repeat purchases. |
| `period` | `status`, included fixed expenses, `contribution_less_incremental_fixed_cost`, `modeled_operating_result_before_tax`, `economic_surplus_after_opportunity_and_displacement`, signs and `operating_break_even` / `economic_break_even`. Break-even orders round up; no positive-volume solution is explicit. Capacity fit is included when supplied. |
| `thresholds` | Allowable CAC for unit contribution, after opportunity cost/displacement, and to cover fixed costs at supplied volume when available. Negative values mean no nonnegative CAC meets that target. `unit_economic_break_even_price` and optional `period_economic_break_even_price` show slope/intercept and minimum actual item price. Nonpositive slope returns no higher-price remedy. |
| `capacity`, `cash` | Explicit assessment status, supplied capacity limit or daily cash balances/funding gap. A cash shortage and positive operating result can coexist. |
| `sensitivity` | Per-scenario overrides, conditional metrics, capacity, and `sign_reversal` against the base economic period result, or unit economic contribution if fixed costs omitted. Zero crossings count as sign changes. Only the listed scenarios were tested. |
| `evidence`, `audit`, `limits` | Supplied source labels, unattributed numeric input paths, original input, equations and model limitations. `evidence_status` remains conditional even with observed inputs. |

Equations and monetary output reconcile before display rounding. No repeat-order revenue, LTV, causal lift or universal target margin enters the arithmetic.
